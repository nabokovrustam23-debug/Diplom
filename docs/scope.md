# Описание проекта (Scope)

> Финальное описание проекта ВКР. Все принципиальные решения зафиксированы здесь.
> Изменения в scope согласовываются с руководителем ВКР.

## Тема

**Разработка модулей системы управления взаимоотношениями с клиентами сети барбершопов «Тихий час».**

Соответствует Приложению В методички ГБПОУ КК ККЭП («Разработка модулей информационной системы…», «Разработка модулей веб-системы…», «Разработка веб-приложения…») для специальности 09.02.07 — Информационные системы и программирование.

## Цель работы

Разработать модули веб-системы управления взаимоотношениями с клиентами (CRM), автоматизирующей ключевые процессы сети барбершопов «Тихий час»: онлайн-запись клиентов, управление расписанием мастеров, ведение клиентской базы, контроль и аналитику работы сети.

## Задачи

1. Проанализировать предметную область (бизнес-процессы сети барбершопов) и существующие аналоги CRM-систем.
2. Сформировать функциональные и нефункциональные требования к системе.
3. Спроектировать архитектуру системы и модель данных.
4. Реализовать модули CRM (см. перечень ниже).
5. Провести модульное тестирование ключевой логики.
6. Подготовить эксплуатационную документацию (руководство пользователя).

## Роли пользователей

| Роль | Авторизация | Возможности |
|---|---|---|
| **Гость** | нет | Просмотр филиалов, мастеров, услуг; запись на приём по имени и телефону. |
| **Клиент** | да | + личный кабинет с историей визитов; быстрая повторная запись; (опц.) бонусные баллы. |
| **Мастер** | да | Своё расписание; отметка о выполнении услуги; заметки о клиенте. |
| **Администратор филиала** | да | Все записи, расписания, мастера и клиенты своего филиала; ручные операции с записями. |
| **Владелец сети (super-admin)** | да | Все операции по всем филиалам; управление филиалами, услугами, мастерами; аналитика по сети. |

## Особенности предметной области («сеть барбершопов»)

- **Мультифилиальность.** В системе несколько филиалов; у каждого — свой штат мастеров и своё расписание. Прайс единый по сети (зафиксировано после обсуждения с заказчиком).
- **Гостевая запись.** Клиент может записаться без регистрации, указав имя и телефон. Авторизация даёт доступ к истории и (опц.) бонусам.
- **Привязка к мастеру.** Запись делается к конкретному мастеру, а не «к любому свободному», — это ключевое отличие барбершопа от парикмахерской.
- **Разная длительность услуг.** Стрижка, борода, комплекс — длительности 30 / 45 / 90 минут; алгоритм поиска слотов учитывает это.

## Что НЕ входит в scope

- ✗ Мобильное приложение (нативное iOS/Android). Ограничиваемся адаптивным веб-интерфейсом.
- ✗ Реальная интеграция онлайн-оплаты. При необходимости — эмуляция.
- ✗ Складской учёт расходников (шампуни, масла, продажа товаров).
- ✗ Расчёт зарплаты мастеров (можно вынести в развитие проекта).
- ✗ Telegram-бот, голосовые ассистенты, прочие интеграции.
- ✗ Графическая часть ВКР (чертежи А1/А2). По образцу ВКР данного руководителя — не требуется.
- ✗ Экономическое обоснование. По образцу ВКР данного руководителя — не требуется.

## Риски и допущения

- **Стек требует подтверждения.** Если будет выбран не C#/ASP.NET Core, главы 1, 2 и часть 5.1 переписывать не нужно — стек фигурирует только в главе 3 и местами в приложениях.
- **Объём ПЗ — 35–50 листов.** Текущий план укладывается; перечень модулей при необходимости сокращается за счёт расширений (М7, М8).
- **Для развёртывания на защите** требуется ноутбук с установленными SQL Server (LocalDB достаточно) и средой запуска приложения (зависит от выбранного стека).
