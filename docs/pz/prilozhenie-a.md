# Приложение А
## (обязательное)
### Техническое задание на разработку модулей программного приложения для управления взаимоотношениями с клиентами сети барбершопов «Тихий час»

## А.1 Общие сведения

**А.1.1 Наименование разработки.** Информационная система управления взаимоотношениями с клиентами сети барбершопов «Тихий час» (далее — «Система»).

**А.1.2 Заказчик.** Сеть барбершопов «Тихий час» (Краснодарский край: Краснодар, Сочи).

**А.1.3 Исполнитель.** Студент группы 23-Д9-4ИСП ГБПОУ КК «Краснодарский колледж электронного приборостроения» Набоков Рустам.

**А.1.4 Сроки разработки.** В соответствии с графиком выполнения выпускной квалификационной работы.

**А.1.5 Форма передачи.** Исходный код в публичном Git-репозитории, развёрнутая копия в среде разработки, пояснительная записка с приложениями.

## А.2 Назначение и цели разработки

**А.2.1 Назначение Системы.** Автоматизация деятельности сети барбершопов в части ведения справочников филиалов, услуг и мастеров, ведения расписаний мастеров, приёма онлайн-записей от клиентов и управления жизненным циклом записи.

**А.2.2 Цели разработки:**
- сокращение трудозатрат администраторов сети на ручное ведение журнала записей;
- снижение количества потерянных бронирований за счёт автоматического исключения занятых слотов из выбора;
- формирование цифрового следа взаимодействия с клиентами;
- получение единого канала онлайн-записи для всех филиалов сети.

## А.3 Требования к Системе

### А.3.1 Функциональные требования

В таблице А.1 приведены функциональные требования, обязательные к реализации.

Таблица А.1 — Функциональные требования

| Код   | Требование                                                                                                          | Приоритет |
|-------|---------------------------------------------------------------------------------------------------------------------|:---------:|
| FR-1  | Учёт справочника филиалов сети с указанием названия, адреса, телефона и часов работы                                 |   must    |
| FR-2  | Учёт справочника услуг сети с указанием названия, описания, длительности и цены                                      |   must    |
| FR-3  | Учёт справочника мастеров с указанием персональных данных (Persona), должности, биографии и привязок к филиалам/услугам |   must    |
| FR-4  | Ведение расписаний мастеров с типами интервалов: рабочее время, обед, выходной, отпуск                                |   must    |
| FR-5  | Гостевая онлайн-запись на приём в виде мастера из 5 шагов: филиал → услуга → мастер → дата/время → контакты          |   must    |
| FR-6  | Расчёт свободных слотов с шагом 15 минут с учётом расписания, перерывов и существующих записей                       |   must    |
| FR-7  | Хранение контактных данных клиента и истории его записей                                                              |   must    |
| FR-8  | Административная панель владельца сети с CRUD-операциями над филиалами, услугами, мастерами                           |   must    |
| FR-9  | Журнал записей с фильтрацией по статусу и возможностью изменения статусов («Создана» → «Подтверждена» → «Завершена» / «Отменена») |   must    |
| FR-10 | Ролевая модель доступа: Гость, Клиент, Мастер, Владелец, Администратор                                                |   must    |
| FR-11 | Защита маршрутов административной панели от пользователей без роли «Владелец»                                         |   must    |
| FR-12 | Защита от удаления справочных записей при наличии связанных бронирований                                              |   must    |
| FR-13 | Идемпотентный сидинг тестовых данных в среде разработки                                                              |   should  |
| FR-14 | Личный кабинет клиента с историей записей                                                                            |   could   |
| FR-15 | Автоматические напоминания клиентам по SMS / e-mail                                                                  |   wont    |

«must» — обязательное к реализации; «should» — желательное; «could» — допускается реализовать; «wont» — выходит за рамки текущей выпускной квалификационной работы.

### А.3.3 Требования к технологическому стеку

Для реализации Системы должен использоваться следующий технологический стек:
- серверная программная платформа: ASP.NET Core 8;
- язык программирования: C# 12;
- шаблонизатор: Razor Pages;
- система управления базами данных: Microsoft SQL Server 2019;
- объектно-реляционное отображение: Entity Framework Core 8;
- система аутентификации: ASP.NET Core Identity;
- система контроля версий: Git, размещение в публичном репозитории на GitHub;
- библиотека модульного тестирования: xUnit.net 2 с провайдером Microsoft.EntityFrameworkCore.InMemory.
